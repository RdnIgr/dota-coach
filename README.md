# Dota Coach

Аналитика рейтинговых игр Dota 2 для пяти игроков одного стака по открытым данным OpenDota. Сайт статический (GitHub Pages, папка `docs/`), данные обновляет GitHub Actions каждые 3 часа.

## Как устроено
- `players.json` - список игроков (Steam ID64 и account_id OpenDota). Новый игрок = еще одна строка.
- `pipeline/fetch.py` - забирает историю матчей, агрегаты по режимам, запрашивает парс свежих реплеев и вытаскивает из разобранных матчей признаки (линия на 10 минуте, смерти с убийцей, предметы, варды, драки). Пишет компактные JSON в `docs/data/<account_id>/`.
- `pipeline/analyze.py` - считает слои методики (METHOD.md): общая картина, герои, смерти, привычки, разобранные реплеи, журнал ошибок. Доверительные интервалы Вилсона 95%, перестановочный тест на случайность. Пишет `analysis.json`.
- `docs/` - фронтенд без сборки: `index.html`, `app.js`, `style.css`. Вкладка на каждого игрока и вкладка «Сравнение» (чекбоксы, графики, таблица, общие игры).
- `docs/data/narrative/<account_id>.json` - текст тренера (вердикт, плюсы, минусы, план). Необязателен; без него вкладка показывает только автоматические находки.
- `.github/workflows/update.yml` - расписание. Можно запустить вручную: Actions -> update-data -> Run workflow.

## Запуск локально
```
python pipeline/fetch.py        # ~5 минут на первый прогон без ключа
python pipeline/analyze.py
python -m http.server 8080 --directory docs
```
Ключ OpenDota необязателен; если есть - положить в секрет репозитория `OPENDOTA_API_KEY` (лимит вырастет, паузы между запросами уменьшатся).

## Тренер на модели
- `pipeline/coach.py report` - полный отчет тренера по игроку (раздел 7 методики): пишется, когда отчета нет или с прошлого прошло 30+ рейтинговых игр. Результат - `docs/data/narrative/<account_id>.json`, предыдущие версии в `narrative/history/`, журнал проверок в `docs/data/<account_id>/coach_log.json`.
- `pipeline/coach.py review` - разбор матча (раздел 5): каждый час `coach-review` берет свежие игры за 48 часов, просит OpenDota разобрать реплей и, когда он готов, модель пишет разбор. Результат - `docs/data/<account_id>/reviews/<match_id>.json`, показывается на вкладке «Разбор матча» и в списке на вкладке игрока.
- Конкретный матч вручную: Actions -> coach-review -> Run workflow -> номер матча (и account_id, если нужен один игрок).
- Числа модель получает готовыми из досье (код считает), ей запрещено придумывать цифры; ответ - строгий JSON. Модель по умолчанию `claude-opus-5-5` (переменная `COACH_MODEL`).
- Ключ: секрет репозитория `ANTHROPIC_API_KEY`. Без него эти шаги пропускаются, остальной сайт работает.

## Если у игрока пусто
OpenDota видит матчи только при включенной настройке Dota 2: Настройки -> Social -> Expose Public Match Data. Сбор каждый раз просит OpenDota подтянуть историю таких аккаунтов, данные появятся после включения настройки.

## Почему без базы данных
Данных на пять игроков - несколько мегабайт JSON, они лежат прямо в репозитории и отдаются Pages со сжатием. Отдельная база (Firebase и подобное) понадобилась бы только для записи из браузера (например, заметки игроков) - тогда ее можно добавить, не меняя остального.
